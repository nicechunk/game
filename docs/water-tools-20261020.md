# 锻造容积与取水工具

> 后续变更：当前已采用默认关闭的可选“采水”属性，并完成 Devnet 和官网 0.1.99 发布。本文下方保留最初的本地实现记录，其中自动认证与拆笔认证方案已被取代；当前规则见 [可选采水发布记录](water-opt-in-20261020.md)。

## 当前规则

- 锻造台铸造后，在右侧属性显示有效承水腔的“容积”；没有有效容积时隐藏。
- 铸造台显示的是对最终提交字节的预览。装备的实际取水资格来自合约对不可变模型账户的几何认证，客户端不能提交容量数字来获得资格。
- 物品、装备与市场展示读取同一份链上容积元数据，单位精确到整 mL，几何计算结果向下取整。
- 仅普通自然水块（block 17）可用于取水。水块保持原状，可重复获取；背包资源 ID 为 8，每份恰好 **1000 mL、1000 g**。
- 每份需要 `ceil(1000 / 容积mL)` 次实际工具接触。100 mL 为 10 次，500 mL 为 2 次，720 mL 为 2 次；大于等于 1000 mL 为 1 次。
- 玩家最新确认：**取满一份后重新累计，超过 1000 mL 的部分不保留**。大容器每轮也只获得一份水。
- 每轮中间接触在本地计数；完成一份时提交一笔交易，合约自行计算次数，同时扣除对应耐久并严格入账一份水。中途不提交链上余量。
- 整笔交易失败时，物品入账、耐久和防重状态全部回滚。背包满载不会白扣耐久。取水不修改地形、采矿计数或 Skills。

## 权威输入与兼容

1. Backpack 指令 20 从真实 ForgedItem PDA 内的 NCF1 字节恢复实体；使用 1/2048 m 的整数边界，压缩没有实体变化的坐标平面，保留真实孔洞。
2. 检查开口、侧壁、底部、握持表面及握持主体和承水腔的面连通；封闭盒、侧漏、缺底、悬空握持和断开的手柄不获得容积。
3. ForgedItem v1 账户仍为 752 字节：保留区 90..94 写入 u32 mL，94..96 保存规则版本及腔体种子。原始模型、实例来源和代码保持不变；旧物品未认证时容量为 0。
4. Chunk 指令 24 验证自然水目标、地形覆盖状态、权限、距离、实际托管装备、已认证物品 PDA，以及装备内完整模型字节和认证模型的一致性。水量和扣耐久次数均由合约决定。
5. Player 指令 19 仅接受取水程序 PDA 的签名。Backpack 指令 21 仅接受相同授权，验证玩家当前装备的背包并存储标准水资源。
6. 单调 action ID 阻止重复结算。客户端在发送前记录公开交易签名；结果未知时先查询状态和链上防重账户，避免重新发送一次取水。

本次保持既有锻造投料政策。认证另行核对实体几何体积与模型编码的材料体积字段；原有锻造合约目前不以实际投料体积作为设计尺寸上限，不能把该字段称为新的投料经济约束。

## 实现边界

当前认证姿态为 +Y 向上，认证选定的一个有效承水腔；客户端自动选择已识别候选中容量最大的腔。支持组件和合法有向面片，不要求固定容器模板。

- 同一腔的多个相互遮挡开口、弯颈及一般复杂拓扑尚未完整支持，无法认证时没有取水属性。
- 软布料不作为刚性不透水壳认证；完整人体碰撞规则仍由现有锻造客户端处理。链上包含基础握持表面和主体连通检查。
- 每轴最多 63 个压缩坐标点，总单元少于 65535；认证请求 256 KiB heap、最多 140 万 CU。尚未实现复杂几何的分阶段认证。
- 组件编码能装入 640 字节时，锻造台保留组件精度。渲染与碰撞使用相同的 2048/m 精度；外观烘焙本身仍受现有 24³ 表达范围限制。
- 包体超限时先完成锻造，再单独认证。认证未完成时装备已经存在，界面会显示容积认证待完成；SDK 提供独立认证入口。

## 本轮验证

独立本地目录：`/workspace/water-tools-20261020/`。SBF 测试通过 LiteSVM 执行实际 ELF，无公网广播；使用历史公开账户快照，交易签名校验关闭，权限及 CPI 分支仍由 SBF 程序执行。本轮没有部署 Devnet/Mainnet 或推送 GitHub。

- 原生合约测试：120 项通过，覆盖 Backpack、Player、Chunk；包含容量元数据兼容和几何正反例。
- 客户端/引擎针对性检查：109 项通过；覆盖容量几何、保留实体编码、缓存精度、取水次数、只结算完整单位、零本地耐久变更、无地形删除、市场属性与既有采集回归。
- 浏览器：实际锻造台铸造后显示容积；侧漏、缺底及无握持模型不显示。属于属性面板检查，不能代替完整 3D 渲染回归。
- 90 笔本地 SBF 交易通过：完整锻造 + 认证 + Skills 同步、28 组真实 NCF1 正反例、整升取水、重复水源、防重、背包满载回滚、耐久耗尽、模型不匹配、非法目标、99 份堆叠边界及代理会话过期。
